## 目标与约束

当前 benchmark 为 codingeval。先利用题面和仓库中可观察的路径、符号、文案，以 bash/rg 和局部读取定位；有明确的关系信息缺口时再选择图工具。避免每题强制 explore；困难题也可完全使用普通工具。只对工具选择作提示，不添加独立 LLM 路由调用、题号分支或硬性搜索次数门槛。

保留预建索引及其调用顺序。原 benchmark 计时与 grading 不变；不把预建索引的变化作为速度收益。Headroom 默认 on，SDK MCP、权限、模型与推理参数不变。源码与任意 bash 输出的压缩策略本批不改，避免混淆消融因素。

允许按当前数据集常见的 ArkTS 页面/状态/路由/SDK 问题优化通用工作流。不得读取/编码参考补丁、隐藏断言、历史正确性标签或未来提交；这些数据不参与在线工具选择。

## 实现

1. indexed 与 no-root-index 初始化说明同步采用 bash 优先。路径/符号已知则直接定向查找；优先编辑已有充分证据支持的位置。
2. tools/list 不再把 explore、usages、modules、native 描述为必选首工具。explore 用于未解决的跨符号机制；精确关系问题优先更小的对应工具。保留查询参数与实际检索实现。
3. 明确源码范围、完整性和版本约束；缺失/截断必须补证据；检索完成不代表完成编码或通过验证。重复探索无新增信息时转定向源码检查。
4. codingeval 配置 CODINGEVAL_HOMEGRAPH_MODE=on_demand|off，默认 on_demand。off 只关闭该 MCP 服务并阻止其工具被继承启用，预建索引仍执行，与 on_demand 保持一致以隔离变量。两组共用 bash 优先工作流和 Headroom。模式保存到每题审计元数据。
5. A 使用保留的 049，B 使用 050/off，C 使用 050/on_demand。B/C 是主要单变量比较；A/C 同时包含提示变化，必须注明。
