# 0023 Task-aware query plan validation

- 类型：变更；日期：2026-09-05。
- 状态：实现完成；2026-09-07 完成全量推理与轨迹保存验证。正确性验收仍需独立审查。
- 范围：QueryPlan 验证、工具任务上下文和有界的检索范围保护；不改建图底层，不改被测题目或注入金标答案。

## 背景

五题 Qwen smoke 中，003/011 的关键词查询被当成全仓 overview，输出相同目录图；033 的模糊锚点落到 wearable，业务需求范围被丢失。成功 JSON 不等于有效检索计划。

## 行为

1. 模型不能把非显式全仓/模块概览请求升级成 project map；具体功能、符号或行为定位的 overview 建议退化为聚焦 general 检索，并保留动作与范围。对显式工程总览保持兼容。
2. explore 可选 taskContext 保存原任务（由 Agent 调用传入或一次会话环境提供），规划时同时保留当前 query 和原任务的动作、对象、否定与范围。该上下文仅用于检索，不能视为源码证据。
3. 模型给出未验证的符号时不作为确定锚点宣称命中；没有证据时保守输出。保持既有时间、输出、步骤预算，不扩大到无限搜索。
4. 指引要求代码修改前核对目标产品与真实定义，任务分解保留原验收项；不以 ANSWER NOW 禁止必要的修改前验证。
5. 显式 HOMEGRAPH_MCP_TOOLS 配置优先于小仓库的默认工具裁剪：使用方明确选择 usages/modules/native 等工具时必须实际暴露，避免指引与 tools/list 不一致。未配置时维持默认裁剪行为。
6. 检索查询不拼入框架自身的说明词（如 `not code evidence`），避免 `code` 等词变成无关图搜索种子。原题与当前查询仍作为有界数据保留。
7. 会话原始任务上下文先于 Agent 提供的简写上下文保留；简写只能补充，不能替换原始路径和子要求。
8. 规划默认预算仍为5秒；显式配置可在1个工具总预算内提高，最多10秒，并预留至少1秒检索时间。自托管Qwen实验用10秒，以覆盖已观测6.8–7.8秒响应。步骤ID接受唯一的字母/数字短标签，仍禁止循环和前向依赖。
9. 已发出模型请求后回退的规则计划不走 MCP 主线程无 deadline 包裹的 fast path，复用原绝对 deadline 进入受限检索分发；未发出模型请求的纯规则 fast path 保持兼容，以离线集成测试验证。
10. 显式llm且有非空原任务上下文时，非精确自然语言查询不能仅因已有mechanism/usages/UI shape命中而跳过规划。明确应交给内置工具的请求与精确符号/路径bag仍优先走低成本路径；无上下文的规则资格兼容旧行为，默认rules/off不发请求。该资格不是正确性或充分性的保证。
11. 规划决策在紧凑诊断中记录planningEligible、planningReason、skip_reason与原ruleRoute；与modelRequests、fallbackReason分别表示资格、实际请求、采用/回退。provider成功和失败均保留决策，不输出完整任务或凭证。
12. 真实probe表明模型可能输出5步Agent工作流而非最多3步检索计划。规划提示提供紧凑JSON形状、明确只找现有定义/引用/配置证据，不能安排写入/删除/构建/测试动作。1–3步骤校验不放宽，越界单独标记invalid_plan_step_count；不自动重试或截掉后续步骤伪造合法计划。
13. 子查询的检索焦点必须与整题约束分离：原query/taskContext继续参与模型输入、作用域与否定约束、缓存身份，但不能把整题全文重复作为每一步同权词法种子，淹没步骤目标。一般检索与mechanism快路径应实际消费本步骤检索hints和已确认的前驱节点，而非只在诊断中保留。默认rules单步保持兼容。
14. 原文mentions、自然语言searchTerms和源码已验证节点应区分。中文或英文自然语言词不因出现在原题里就被认为已定位到符号；真实中文代码标识符仍允许经索引验证。前驱绑定必须对应本步骤实际证据，并保留可区分同名节点的路径身份；不能将继承节点的再次命中当作本步骤目标已解决，也不能将全局模糊搜索近邻直接升级为可信绑定。缺证据应保持未解析，不通过放松依赖门槛制造执行成功。
15. 检索单查询诊断不等于Agent正确率。真实MCP执行需分开统计计划采用、实际执行/未执行步骤、业务证据充分性与总成本。后继未执行造成输出变短不能视为token优化；SDK/设备缺失不能宣称准确率。下一次Agent批次前先通过通用合成回归和只读base上的真实检索审查，禁止按题号/金标符号做特例。
16. 首版只对LLM general/flow跳过尚不消费结构化hints的旧fast路径，复用已有完整explore；rules与专用工具路径保持兼容。步骤可选searchTerms向后兼容，原题约束在最终输出只展示一次，不作为每步同权种子；修改范围并不等于禁止只读查看相关范围外代码，不用产品关键词猜测硬过滤。
17. 完整explore从最终实际展示的文件和声明起始行形成有界locatedNodes记录；前驱按id和文件身份消费，而不是再用裸名称全库搜索。多步拼接裁剪前先为拟传递的记录保留计入预算的源码位置摘要；未展示的候选、只有父类片段但未展示声明头、继承节点的自我重复、尚无结构化记录的快捷section不产生新绑定。记录仅说明节点存在且已展示，不能宣称已找对业务目标。

18. 本次语言对照仅修改内部规划SYSTEM提示：要求每步query用英文自然语言，顶层与每步searchTerms用拆开的简短小写英文语义词；真实标识符（含中文）、路径与字面量原样保留，不翻译、不猜造复合类名，原范围/否定约束不丢。仍为一次既有规划调用，不加翻译模型/词典/语言硬校验，不改变检索实现、锚点校验或预算。先用同一记录query和不可变base复测，明确区分语言遵循、候选召回和业务证据充分性；不能以一次命中宣称统计收益。
