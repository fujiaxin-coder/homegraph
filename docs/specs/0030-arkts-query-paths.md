## 目标

第一批保留完整源码，但主要展开一跳邻居，可能漏掉连接两个端点的中间方法。
第二批使用已有查询计划和真实符号身份，按关系类型和方向查找有限的静态路径，
优先把路径所需源码放入证据包，减少无关邻居和外部补查轮次。

## 契约与行为

1. 内部 EvidencePathGoal 区分调用、事件、状态、结构关系以及方向。复用现有
   QueryPlan 的关系、特征与已验证绑定；没有明确方向时寻找任一方向上的完整
   有向路径，不能把 A→C←B 当成 A→B。名称歧义保留为缺口，不任取同名方法。
   现有语义分词会省略 start 等常见词；对查询/planner 中最多 4 个精确限定名，
   允许通过 qualified_name 索引补齐候选（点号/双冒号两种形式，每次最多 25 行），
   不能因此把整个类或某个同名方法当成所请求的端点。
2. 仅使用已有静态图。调用路径不走 imports/contains/returns 捷径，不将普通
   references 或状态刷新当成确定的调用。事件/状态图元信息保留其具体语义。
3. 优先直接关系；缺少连接时在同一次请求内进行一次有界路径搜索。候选排序
   区分关系适用性、来源可靠性与搜索代价，不把代价或启发式分数称为正确概率。
4. 最多 4 个端点、3 个相邻端点对、4 跳；数据库单次邻接读取限量，搜索还有
   总读取次数、节点数和墙钟预算。无路径意味着本次范围内未找到，不证明不存在。
5. 完整路径作为一个证据包选择：所有中间声明和必要注册位置均实际返回后，
   才能声明路径证据已提供。源码过期、缺失或预算不足时显示 Gap，不能只输出
   两端箭头就声称路径完整。独立的一跳证据可以继续提供。
6. 输出记录目标、实际有向路径、停止原因、搜索规模及补查线索；不新增外部工具
   或模型调用，不让工具宣布编码任务完成。多步 planner 继续沿用第一批共享预算。
7. `HOMEGRAPH_ARKTS_QUERY_PATHS=0` 在第一批证据包上关闭第二批策略；
   `HOMEGRAPH_ARKTS_EVIDENCE_PACKS=0` 仍关闭整个证据包渲染器。缓存隔离开关。

## 范围与边界

- HomeGraph 内部查询、MCP 证据选择和描述；不改 codingeval、旧目录或预建索引。
- 专用 usages/modules/native 工具和字面量/资源定位路径保持现有行为。
- 不增加解析/合成边，不实现 CFG、时序证明、向量检索、自动多轮 Agent 或按题号规则。
- 只使用查询和当前源码/索引；不读取答案、隐藏测试、未来修复信息。
- Headroom 继续使用外部 0.37.0 无损策略，并真实执行兼容检查；不把其放入 MCP 依赖。
- 合成检索检查用于正确性和局部比较；不能替代 codingeval 真实推理的时延/准确率测量。
